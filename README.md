# Pig 7 Gara

Система защиты и модерации Telegram-каналов. Самостоятельный проект на основе Pig 6.1.

## Возможности

- Защита владельца и подключённых каналов с ротацией невидимого UUID.
- Фильтрация содержимого, запрет GIF и очистка флуда.
- Проверка содержимого отредактированных постов без повторного учёта публикации.
- Панель управления: защищённые и alpha-пользователи, TRUST, mute и EXCOMMUNICADO.
- Shadow: анонимные каналы, подписки, суточные лимиты и раскрытие автора по ссылке.
- Judgment Day: удаление входящих и изменённых сообщений во всех доступных боту чатах.
  Сообщение с текущим непустым кодом в тексте или подписи пропускается; после использования код меняется.
- Стикеры-цитаты и получение текста или поддерживаемого медиа в личные сообщения.
- Джарвис: AI-диалог и административные команды для владельца и root-пользователей.
- Сайт с описанием системы и политикой безопасности.
- Веб-предложка без входа через Telegram: очередь текстов, публикация и блокировки из бота.
- Журналирование с маскированием токенов и отдельным аудитом действий панели.
- Публичный рейтинг администраторов по суммарному количеству реакций на их посты.

## Запуск

Создайте `.env` в корне проекта:

| Переменная | Назначение |
| --- | --- |
| `TOKEN` | Токен основного бота |
| `JUDGMENT_DAY_TOKEN` | Токен бота Judgment Day |
| `AI_TOKEN` | Токен Джарвиса |
| `GEMINI_API_KEY` | Ключ Gemini для Джарвиса |
| `OWNER_ID` | Telegram ID владельца |
| `OWNER_USERNAME` | Username владельца для уведомлений |
| `MAIN_CHANNEL_ID` | ID основного канала |
| `PERSONAL_CHANNEL_ID` | ID канала владельца |
| `WEB_SITE` | Публичный адрес сайта для ссылки на политику безопасности |
| `SUGGESTIONS_DB` | Необязательный путь к общей базе предложки (по умолчанию `suggestions.db`) |
| `FORWARDED_ALLOW_IPS` | IP доверенного reverse proxy для Uvicorn, если сайт работает через прокси |
| `LOGS_TOKEN` | Токен дополнительного бота пересылки публикаций, если он используется |

```bash
docker compose up --build -d
docker compose exec pigbot supervisorctl status
```

Supervisor запускает пять процессов:

| Процесс | Команда | Назначение |
| --- | --- | --- |
| `bot1` | `python main.py` | Основной бот |
| `bot2` | `python -m bot.logs` | Пересылка публикаций подписчикам |
| `bot3` | `python -m bot.jday` | Judgment Day |
| `bot4` | `python -m AI.ai` | Джарвис |
| `api` | `uvicorn web.server:app --host 0.0.0.0 --port 2322 --no-access-log` | Сайт и приём заявок |

Для `bot2` задайте `LOGS_TOKEN` в `.env`. Пересылка включается настройкой `logs_mode`.

## Управление

Основные команды: `/start`, `/reg`, `/myaccess`, `/sub`, `/rating`, `/q`, `/quote`, `/d`, `/download`.

Команды владельца и root-пользователей: `/panel`, `/blockall`, `/smart`, `/disable`,
`/jday`, `/jcode`, `/post`, `/link`, `/config`, `/setbaseprompt`.
Команда `/logs` также доступна пользователям с TRUST.

Для подключения обычной защиты опубликуйте `protect` в своём канале и дождитесь
одобрения. `unprotect` отключает защиту. Для Shadow оставьте владельца и бота
в администраторах канала, разрешите боту менять информацию и опубликуйте `Shadow`.

В основном канале `/bangif` ответом на GIF добавляет его в запрещённые.
`EXCOMMUNICADO` запускает соответствующий протокол по проверкам доступа.
Административные действия не выполняются при редактировании поста.

## Данные

- `config.json` — настройки и зарегистрированные пользователи. Образец: `config.json.example`.
- `shadow.json` — каналы, подписки, лимиты и архив авторства. Образец: `shadow.json.example`.
- `rating.db` — авторы учтённых постов и последние счётчики реакций; создаётся автоматически.
- `suggestions.db` — очередь веб-предложки, технические данные для блокировок и статусы модерации.
- `dict.json` — нормализация символов для фильтра содержимого.
- `web/security-policy.txt` — текст политики безопасности, перечитываемый без перезапуска.
- `logs/` — журналы работы и аудита.

Новые пользователи Shadow получают Plus на календарный месяц. `/sub` показывает
текущий тариф, срок и остатки лимитов; лимиты сбрасываются в 00:00 по Москве.
Для просмотра автора отправьте основному боту ссылку на Shadow-пост.

`/rating` показывает топ-20 администраторов основного канала. Одна реакция любого
вида даёт один балл: 👍, 👎 и остальные реакции равнозначны. Баллы суммируются по
постам автора; снятие реакции уменьшает счёт, а замена эмодзи при том же количестве
баллы не меняет. Повторные и устаревшие обновления не начисляются заново.

Автор определяется при публикации до смены UUID и не меняется при редактировании.
Учитываются новые посты с определённым автором, включая публикации через `/post`.
Старые посты без сохранённого авторства и Shadow-публикации в рейтинг не входят.
Снятые ботом при модерации посты исключаются. Для реакции на вручную удалённый пост
сохраняется последний известный счётчик: Telegram не присылает боту событие такого удаления.
Счётчики анонимных реакций могут приходить с задержкой в несколько минут.

Сайт доступен на порту `2322`. Страница политики: `/security-policy`.
При изменении `.env` перезапустите процессы.
Ботам необходимы соответствующие административные права в подключённых чатах.

## Веб-предложка

Форма `/suggest` принимает текст до 3000 символов, работает с JavaScript и без него.
Telegram-входа нет. Из технических данных сохраняются IP-адрес и хеш случайной
cookie браузера; также сохраняются текст, время, номер и статус заявки. Cookie
HttpOnly, SameSite=Strict, действует 180 дней; на HTTPS устанавливается Secure.
Для публичной формы используйте HTTPS. Утверждения о полной анонимности нет.

Основной бот проверяет очередь каждые 5 секунд и отправляет заявки владельцу и
root-пользователям в личку, вместе с IP отправителя. Они должны предварительно открыть диалог с ботом.
Кнопки позволяют опубликовать, отклонить или отклонить с блокировкой IP и cookie.
Общий IP может затронуть других посетителей; блокировку можно снять кнопкой в
уведомлении. В очереди может быть не более 200 ожидающих заявок.
Смена IP и браузера позволяет обойти блокировку.

Публикация идёт от бота без подписи пользователя и не добавляет баллов в рейтинг.
Shadow и поиск авторства не используются. Модератор проверяет содержимое перед
публикацией; Judgment Day и полный запрет сообщений приостанавливают отправку.
При неоднозначном ответе Telegram или перезапуске во время отправки бот просит
проверить канал вручную, прежде чем повторять публикацию.

После решения текст удаляется из базы предложки, уведомления редактируются в
статус без текста и IP (при блокировке IP остаётся до её снятия). Остальные данные закрытой заявки удаляются через 30 дней
(очистка раз в час при работающем основном боте); при блокировке остаются до её
снятия. Telegram обрабатывает текст и IP при отправке модераторам; в канал отправляется только текст.
Запросы формы не записываются в access-log Uvicorn. Проверьте собственные журналы
reverse proxy отдельно.

IP берётся из `request.client`, а не из произвольного заголовка посетителя.
Если сайт за reverse proxy, настройте `FORWARDED_ALLOW_IPS` у процесса Uvicorn
только на адреса доверенных прокси. Иначе все посетители могут определяться как
один прокси. Не используйте `*` при доступном напрямую порте API.
API и основной бот должны использовать один файл `SUGGESTIONS_DB` на локальном
диске; при Docker-запуске по умолчанию он уже находится в общем томе `/app`.

```bash
python -m unittest discover -s tests
```

Тесты используют временные данные и имитацию Telegram API, без запуска ботов.
